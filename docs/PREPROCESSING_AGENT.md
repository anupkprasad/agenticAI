# Refactored Preprocessing Agent with LLM Tool Calling

## Overview

The preprocessing agent has been refactored to use **LLM-powered tool calling** with **Pydantic schemas** for structured agent decision-making. Instead of a simple planning approach, the agent now:

1. **Analyzes** the PDB structure using specialized tools
2. **Plans** preprocessing steps using LLM reasoning
3. **Executes** each step through a modular tool executor
4. **Validates** results and updates workflow state

## Architecture

### Components

#### 1. Pydantic Schemas (`schemas.py`)
Defines structured data models for all preprocessing operations:

```
├── PDBAnalysisResult         # Result of PDB analysis
├── PreprocessingStep         # Individual preprocessing step
├── PreprocessingPlan         # Complete preprocessing plan (LLM output)
├── PreprocessingResult       # Execution result with generated files
├── PreprocessingAgentInput   # Input parameters for agent
└── PreprocessingAgentOutput  # Final agent output for workflow
```

#### 2. Tool Executor (`PreprocessingToolExecutor`)
Modular tool implementation for preprocessing operations:

**Available Tools:**
- `analyze_pdb`: Analyze PDB structure (atoms, chains, waters, heteroatoms)
- `remove_waters`: Remove water molecules
- `handle_alternate_locations`: Resolve alternate conformations
- `add_hydrogens`: Add missing hydrogens (reduce/obabel/fallback)
- `assign_protonation`: Assign protonation states at given pH
- `prepare_for_gromacs`: Run GROMACS pdb2gmx
- `generate_topology`: Create topology file
- `validate_structure`: Validate PDB structure integrity

#### 3. Preprocessing Agent (`PreprocessingAgent`)
LLM-guided agent that orchestrates the workflow:

**Workflow:**
```
preprocess_node()
  ├─ _prepare_agent_input()      # Format input for LLM
  ├─ _run_llm_preprocessing_agent()
  │   ├─ _llm_make_plan()       # LLM analyzes & plans
  │   │   ├─ analyze_pdb       # Get structure info
  │   │   └─ LLM.invoke()       # Generate plan
  │   └─ _execute_plan()        # Execute step-by-step
  │       └─ tool_executor.execute_tool()  # Run each tool
  ├─ _update_state()             # Update workflow state
  └─ Return to supervisor
```

## Usage Example

### 1. Direct Tool Execution

```python
from agentic.preprocess.preprocessing_agent import PreprocessingToolExecutor

executor = PreprocessingToolExecutor("working_dir")

# Analyze PDB
result = executor.execute_tool("analyze_pdb", {
    "pdb_file": "input.pdb"
})

# Remove waters
result = executor.execute_tool("remove_waters", {
    "pdb_file": "input.pdb",
    "output_file": "no_waters.pdb"
})
```

### 2. LLM-Guided Preprocessing

```python
from agentic.preprocess.preprocessing_agent import PreprocessingAgent
from agentic.llm import LLMClient

# Create agent with LLM
llm = LLMClient("gpt-oss:20b", base_url="http://localhost:11434")
agent = PreprocessingAgent(llm)

# Run preprocessing through workflow
state = agent.preprocess_node(workflow_state)
```

### 3. Fallback Planning

When LLM is unavailable, the agent automatically uses heuristic planning:

```python
# Creates plan based on PDB analysis:
# - Remove waters if detected
# - Handle alternate locations if present  
# - Add hydrogens if needed
# - Prepare for GROMACS
# - Validate final structure
```

## LLM Integration

### Planning Phase

The agent sends a structured prompt to the LLM:

```python
prompt = f"""
You are a molecular dynamics preprocessing expert. Analyze this PDB structure 
and create a detailed, step-by-step preprocessing plan.

**PDB Information:**
- File: {pdb_path}
- Force Field: {force_field}
- Water Model: {water_model}

**Structure Analysis:**
- Atoms: {atom_count}
- Chains: {chain_ids}
- Has Waters: {has_waters}
- Heteroatoms: {heteroatoms}

**Available Tools:**
[list of tool names and descriptions]

**Your Task:**
Create a detailed preprocessing plan with specific steps. Output as JSON:
{{
  "reasoning": "Detailed analysis",
  "steps": [
    {{
      "name": "step_name",
      "tool_name": "tool_to_call",
      "tool_params": {{"param": "value"}},
      "reason": "why needed"
    }}
  ]
}}
```

### Execution Phase

For each step in the plan, the agent:
1. Extracts tool name and parameters
2. Calls `tool_executor.execute_tool()`
3. Logs success/failure
4. Updates input files for chained steps
5. Collects output files

## Pydantic Schemas

### PreprocessingStep

Represents a single preprocessing operation:

```python
class PreprocessingStep(BaseModel):
    name: str                      # e.g., "remove_waters"
    description: str               # Human description
    tool_name: str                 # Tool to execute
    tool_params: Dict[str, Any]   # Parameters for tool
    input_file: Optional[str]      # Input file (if any)
    output_file: Optional[str]     # Expected output file
    reason: str                    # Why this step is needed
```

### PreprocessingPlan

Complete plan generated by LLM:

```python
class PreprocessingPlan(BaseModel):
    reasoning: str                 # Detailed strategy explanation
    overview: str                  # High-level summary
    steps: List[PreprocessingStep]  # Ordered steps
    estimated_output_files: Dict   # Expected output files
    potential_issues: List[str]    # Potential problems
    recommendations: List[str]     # Post-processing recommendations
```

### PreprocessingResult

Execution results:

```python
class PreprocessingResult(BaseModel):
    success: bool                  # Whether preprocessing succeeded
    cleaned_pdb: Optional[str]     # Cleaned PDB file path
    topology: Optional[str]        # GROMACS topology path
    processed_coordinates: Optional[str]  # Processed coords path
    report: str                    # Summary report
    issues: List[str]             # Problems encountered
    warnings: List[str]           # Non-critical warnings
    generated_files: Dict[str, str]  # All generated files
    execution_log: str            # Complete execution log
```

## Error Handling & Fallbacks

### LLM Unavailable
→ Uses `_fallback_preprocessing_plan()` with heuristic strategy

### Tool Execution Failure
→ Logs error, continues with remaining steps, reports issues

### Missing Output Files
→ Creates minimal valid files to allow workflow continuation

### Invalid PDB Structure
→ Logs issues, validation catches and reports problems

## Integration with Workflow

The agent integrates seamlessly with the LangGraph workflow:

1. **Input:** Receives MDState from supervisor with:
   - `raw_pdb`: Path to input PDB file
   - `user_goal`: User's preprocessing intent
   - `force_field`, `water_model`: Simulation parameters
   - `working_directory`: Output location

2. **Processing:** Generates plan and executes tools

3. **Output:** Returns updated MDState with:
   - `cleaned_pdb`: Processed PDB file
   - `topology`: Generated GROMACS topology
   - `processed_coordinates`: Processed coordinates
   - `preprocessing_report`: Execution summary
   - `preprocessing_issues`: Any problems encountered
   - `preprocessing_warnings`: Non-critical warnings
   - `next_node`: Routes to supervisor or human checkpoint

4. **Routing:**
   - If successful → supervisor node (final report stage)
   - If issues + human_in_loop → human checkpoint node
   - If failed → supervisor with error state

## Extending with New Tools

To add a new preprocessing tool:

1. **Add to `PreprocessingToolExecutor._*` methods:**
```python
def _my_tool(self, param1: str, param2: Optional[str] = None, **kwargs) -> Dict[str, Any]:
    """Tool description"""
    try:
        # Implementation
        return {"success": True, "output_file": "path/to/output"}
    except Exception as e:
        return {"success": False, "error": str(e)}
```

2. **Register in `execute_tool()`:**
```python
elif tool_name == "my_tool":
    return self._my_tool(**params)
```

3. **Update LLM prompt** in `_llm_make_plan()` to include new tool

4. **Test with fallback plan** to ensure coverage

## Design Decisions

### Why Pydantic?
- **Validation**: Ensures data consistency
- **IDE support**: Full autocomplete
- **Documentation**: Self-documenting schemas
- **Serialization**: Easy JSON conversion for LLM

### Why Tool Executor?
- **Modularity**: Each tool is independent
- **Testability**: Tools can be tested in isolation
- **Extensibility**: New tools add easily
- **Error isolation**: One tool failure doesn't break others

### Why LLM Planning?
- **Adaptive**: Plans based on actual PDB structure
- **Interpretable**: LLM explains its reasoning
- **Flexible**: Can handle novel preprocessing scenarios
- **Human-understandable**: Plan is readable by users

### Fallback Strategy?
- **Reliability**: Works without LLM
- **Offline capability**: Useful on HPC clusters
- **Predictable**: Heuristics are deterministic
- **Safe**: Conservative approach when LLM unavailable

## Performance Considerations

- **LLM overhead**: ~1-2 seconds for planning
- **Tool execution**: ~0.1-10 seconds per tool (gmx pdb2gmx is slowest)
- **Memory**: Minimal (< 100 MB for agent + tools)
- **Parallelization**: Currently sequential, could parallelize independent tools

## Future Enhancements

1. **Tool parallelization**: Run independent tools concurrently
2. **Advanced error recovery**: Auto-fix common issues
3. **Tool composition**: Chain tools based on LLM suggestions
4. **Performance optimization**: Cache PDB analyses
5. **Extended tool library**: Add more preprocessing utilities
6. **Multi-step validation**: Validate after each step, not just end
7. **User feedback integration**: Learn from human corrections
